# 报销系统主服务器（AI Agent 安全执行与审批平台）

> 企业报销系统的**主服务器**：账号权威在本机 JSON，报销单写入口唯一，四角色权限矩阵，
> 审计哈希链 + 快照回退 + 人工审批，AI 与发票 OCR 由协作方前端调用我们的接口完成。
> 单进程、零第三方 NuGet 依赖、JSON 文件即数据库、开箱可跑的 .NET 8 实现。

仓库地址：<https://github.com/xingyungames/agent-safe-gate>（仓库名 `agent-safe-gate` 指的就是这里的「AI Agent 安全执行与审批网关」）

## 这是什么

一个**报销系统的服务端**，也是 **AI Agent 的安全执行网关**。它把"谁能做什么、写了什么、写错了怎么退回来"全部落在代码里：

| 风险 | 本项目的做法 |
| --- | --- |
| 越权（员工想看别人的报销单、财务想删单） | 四角色权限矩阵 + 数据边界（员工按登录身份姓名过滤，详情再做一次归属校验），服务端强制 |
| 前端或 AI 绕过规则写脏数据 | **报销单只有一个写入口**：枚举白名单、金额区间、状态流转、只读字段全部在服务端校验与盖章 |
| "看起来正常的写入"投毒（脚本、外链、内网地址） | 后缀 ∪ 内容双通道识别可执行文件 + 片段级内容风险扫描，命中即强制人工审批 |
| 机密泄露（口令、凭证） | 口令用"每账号随机盐 + 服务端密钥 + 120 万次慢哈希"存储，拖走 `users.json` 也无法离线爆破；飞书凭证与 AI 密钥只从 `config/secrets.local.json` / 环境变量读，绝不入库入仓 |
| 飞书用户表被整表拖库 | 镜像只写**演示口令**的哈希，真实口令永不出本机；镜像失败静默处理，不影响账号功能 |
| 高危操作点错一次就回不去 | 每次写飞书前存整行快照 + 撤销日志，管理员可按日志一键回退（新建→删除、删除→重建、修改→写回旧值） |
| 事后说不清谁干了什么 | 审计 JSONL 哈希链（`Seq + PrevHash → SHA-256`），支持整链校验与篡改定位 |
| 管理后台被爆破 | 账号锁 + 登录限流 + WAF + 蜜罐诱捕 + 自动封禁，越权访问另记攻击分 |

**一句话概括设计目标**：AI 有"翻译权"，没有"执行权"；写入口、审批权与回退权分持在代码与人类手里。

## 核心特性

- **账号权威 + 飞书镜像**：账号存在本机 `users.json`（加盐 + 服务端密钥的慢哈希、令牌世代、工号），
  同时 best-effort 镜像到飞书用户表；镜像失败只写审计与状态，**注册、登录、改角色都不受影响**。
- **初始超管与账号同步**：全新部署用 `Bootstrap:Admin`（环境变量 `AISERVER_BOOTSTRAP_*` 或 `config/secrets.local.json` 的 `BootstrapAdmin` 段）播种第一个超级管理员，
  推荐只填 `PasswordHash` + `PasswordSalt`，只在账号不存在时创建一次、不写飞书用户表；
  管理端还能手工从飞书用户表**补账号**（`GET /api/admin/users/feishu-rows` 预览、`POST /api/admin/users/sync-from-feishu` 执行，支持 `dryRun`）——
  只补本机没有的账号，已存在账号的口令、角色、启停一律不动，对面的「管理员」也永远不会变成超管。
- **四角色权限矩阵**：超级管理员 / 管理员 / 财务部 / 员工，权限键细粒度分配；
  "授予管理员"仅超管可做，任何人不能改自己的角色，系统必须保留至少一个超管。
- **报销单唯一写入口**：`/api/invoice/*` 由本服务代理写飞书主表，服务端盖章申请人、工号、提交时间、合规结果与状态。
- **合规预审**：无票硬性阻断；招待费超 2000、办公用品超 5000、差旅按城市分级、开票超 30 天记为风险并写摘要。
- **两层 AI 分工**（沿用）：上游 AI 只做意图解析；下游 AI 只做安全审核，**看不到用户原始输入**，只看到 `{intent, 规范化动作}`。
- **确定性硬防线**：规则引擎在 AI 之前做 100% 可预测的校验（路径守卫、参数白名单、权限、业务硬规则），不依赖模型自觉。
- **多步代理循环**：像代码助手一样"先搜 → 再读 → 再写"，只读工具自动连续执行（步数/墙钟双上限），**写操作立即终止循环转审批**。
- **文件操作按"区域 × 可执行性"分级**：私人区普通文本可自动增删查改（覆盖/删除前存快照）；共享区、脚本与可执行文件一律人工审批。
- **人工审批闭环**：任务状态机 + 出站箱/SMTP + **签名一次性审批链接**（与任务绑定、有有效期、用后失效，防 IDOR）。
- **三个前端**：业务工作台 `/`、财务工作台 `/finance`、管理后台 `/admin`。原生 JS、零 emoji、CSP 友好、不使用 `innerHTML`/`eval`。

## 执行链路

```
用户请求
  └─ 鉴权（JWT + 请求签名 + 防重放 + WAF/蜜罐/限流）
      └─ 权限上下文（角色 → 权限键 → 可用工具白名单）
          └─ 注入特征扫描 ──命中──► 强制转人工审批
              └─ AI 规划（多步：只读自动连续执行，写操作立即停下）
                  └─ 规则引擎（硬拦截：路径/权限/参数/业务规则 → ALLOW / ASK / DENY / 需审批）
                      └─ AI 安全审核（物理隔离，只能维持或升级审批等级）
                          ├─ 允许自动执行 ──► Harness 执行 ──► 快照 + 版本 + 审计
                          └─ 需人工审批 ──► 异步落库 + 通知/邮件（签名链接）──► 管理员审批 ──► Harness 执行
```

细节见 [docs/架构与数据模型.md](docs/架构与数据模型.md)。

## 快速开始

前置：**.NET 8 SDK**（无需任何第三方包）、可选 **Node.js 18+**（只用于跑测试脚本）。

```bash
git clone https://github.com/xingyungames/agent-safe-gate.git
cd agent-safe-gate/AiApprovalServer
dotnet run
```

启动后：

| 页面 | 地址 | 说明 |
| --- | --- | --- |
| 业务工作台 | http://127.0.0.1:8899/ | 对话式下指令、看审批状态、撤回申请 |
| 财务工作台 | http://127.0.0.1:8899/finance | 单据列表与筛选、审核、修改、删除（按权限可见） |
| 管理后台 | http://127.0.0.1:8899/admin | 账号与权限管理、审批、按日志回退、审计校验、安全态势、飞书账号同步 |

首次启动会自动生成服务端密钥到 `App_Data/secrets.json`，并播种四个演示账号与一个初始超级管理员（工号按顺序分配）：

| 账号 | 口令 | 角色 | 工号 |
| --- | --- | --- | --- |
| `employee` | `Staff#2026abc` | 员工 | E0001 |
| `finance` | `Money#2026abc` | 财务部 | E0002 |
| `admin` | `SysRoot#2026ak` | 管理员 | E0003 |
| `root` | `Overlord#2026ak` | 超级管理员 | E0004 |
| `xinghan` | `Ss@123456` | 超级管理员 | 播种时按当前最大工号 +1（默认 E0005，若已有四个演示账号则是 E0005） |

> **演示口令与初始超管口令都只是本机体验用的公开默认值**。任何对外可访问的部署都必须先改掉它们，并按 [docs/部署与配置.md](docs/部署与配置.md) 的生产检查清单处理。
> 账号权威在本机 `users.json`；飞书用户表只做镜像，且只写"演示口令"的哈希，见 [docs/飞书镜像对接.md](docs/飞书镜像对接.md)。

初始超级管理员由 `appsettings.json` 的 `Bootstrap:Admin` 播种（也可以用环境变量 `AISERVER_BOOTSTRAP_*` 或 `config/secrets.local.json` 的 `BootstrapAdmin` 段覆盖）：
超管不能通过界面创建，否则全新环境里没人能授予第一个管理员。它在账号库里不存在该用户名时创建一次，之后改口令、停用、删除都照常生效，重启不会把它改回来。
推荐只填 `PasswordHash` + `PasswordSalt`（配置里不出现明文口令），生成方式：`node AiApprovalServer/tools/hash-password.mjs <你的口令>`。详见
[docs/账号与权限设计.md](docs/账号与权限设计.md) 第 9 节。

> **交付/上传前请清空 `config/secrets.local.json`**：它同时装着飞书凭证、AI 密钥与 `BootstrapAdmin` 初始超管口令哈希。
> 文件不存在或清空后服务照常启动：AI 走降级模式、跳过飞书镜像，初始超管则按 `appsettings.json` 里的默认配置播种。

想让报销单真正写进飞书（**写入口统一由本服务代理**）：

```bash
# 复制模板为 config/secrets.local.json 并填真实值（该文件已被 .gitignore 忽略，也不会被复制进发布包）
# {"Ai":{"ApiKey":"sk-xxx"},
#  "Feishu":{"AppId":"cli_xxx","AppSecret":"...","AppToken":"...","TableId":"<报销单主表>","UserTableId":"<用户表>"}}
# AppToken / TableId / UserTableId 也可以直接粘贴飞书网页地址，启动时会自动取出其中的标识
# 环境变量同样可用：AISERVER_AI_KEY / AISERVER_FEISHU_APPID / APPSECRET / APPTOKEN / TABLEID / USERTABLEID
dotnet run
```

未配置飞书时服务照常启动：账号、权限、审批、审计全部可用，只有报销单接口返回 502 `FEISHU_UNAVAILABLE`、镜像标记为 `skipped`。

想接真实模型（默认是**降级模式**：本地意图解析 + 审核不可用 → 全部变更转人工）：

```bash
# Windows PowerShell（推荐环境变量注入；写进 config/secrets.local.json 的 Ai.ApiKey 也可以）
$env:AISERVER_AI_KEY = "sk-your-key"
$env:Ai__BaseUrl = "https://api.deepseek.com/chat/completions"
$env:Ai__Model = "deepseek-chat"
dotnet run
```

不联网也能完整跑通全部功能：仓库自带确定性假模型，见 [docs/测试与验收.md](docs/测试与验收.md)。

## 前后端怎么分工、怎么部署、怎么接入

本仓库是**后端（另自带三个页面）**，协作方的对话式前端是**表现层**：

| 层 | 在哪 | 负责什么 |
| --- | --- | --- |
| 表现层 | 协作方网关 `xiaocainu/`（默认 `http://127.0.0.1:8000`） | 对话交互、AI 意图理解与多轮追问、发票 OCR、把自然语言整理成结构化字段并回显结果 |
| 校验层与平台层 | 本仓库 `AiApprovalServer/`（默认 `http://127.0.0.1:8899`，接口前缀 `/api`） | 账号与权限权威、报销单唯一写入口、枚举与金额硬校验、服务端盖章字段、审批与执行、快照与版本回退、审计哈希链、WAF/蜜罐/限流/签名防重放 |

三个入口最终都打到本仓库后端：**员工**走协作方的对话式前端；**财务**走本仓库 `/finance`；**管理员与超级管理员**走本仓库 `/admin`。
边界一句话：AI 层可以随便理解，落地必须过校验层；校验层拒绝的，AI 层不许绕过。

| 部署形态 | 起什么 | 关键配置 |
| --- | --- | --- |
| 单机演示 | `dotnet run`（本仓库）+ `python -m api.main 127.0.0.1 8000`（协作方网关，**先起本仓库**） | `config/secrets.local.json` 填飞书凭证；协作方 `.env` 里 `BACKEND_BASE_URL=http://127.0.0.1:8899` |
| 前后端分离 | 本仓库只作 API 后端，协作方前端独立部署 | 写请求必须带 `X-Timestamp` / `X-Nonce` / `X-Signature`；跨站写请求还要把协作方前端来源加进 `Security:TrustedOrigins` |
| 生产 | 反向代理终止 TLS，本仓库只监听回环 | 四个后端密钥（`AISERVER_JWT_SECRET` / `AISERVER_AES_KEY` / `AISERVER_PEPPER` / `AISERVER_AI_KEY`）与飞书凭证走环境变量或 `config/secrets.local.json` |

> **需要知道的现状**：登录判定已经收到本仓库——协作方 `AuthService.login` 先调本仓库 `POST /api/auth/login`，由本仓库判定口令；
> 本仓库返回 4xx（口令错误、账号被禁用、账号被锁定、限流）时协作方直接返回 401/429，**不再回落到它自己的飞书用户表**。
> 只有本仓库返回 5xx 或连不上时才看协作方 `.env` 的 `BACKEND_MODE`：`preferred`（默认）用协作方本地用户表兜底，`required` 直接 503 拒绝登录；
> `BACKEND_BASE_URL` 留空（主服务器未启用）时保持原来的"只用本地用户表"的离线演示行为。
> 登录成功后协作方拿本仓库返回的账号资料（用户名、姓名、角色、工号）签发它自己的会话令牌，本仓库四个角色映射到网关三个标签：
> `employee` → 员工、`finance` → 财务、`admin` 与 `superadmin` → 管理员。
> 因此"员工登录判定仍由协作方那张表说了算"已经不成立，那张表现在只在"本仓库连不上且不是 `required` 模式"时才会用到；
> 剩下的已知边界是协作方表里存在、而本仓库不存在的账号：`required` 模式下会被拒绝登录，`preferred` 模式下本仓库不可达时仍能用本地表登录（离线兜底），
> 这种登录没有本仓库会话、提交会回落直连飞书——所以生产仍建议把 `BACKEND_MODE` 设为 `required`。
> 协作方表里已有的账号可以用管理后台的「飞书账号同步」一次性导入（保留原口令可用）。

分工边界、当前登录链路的完整说明、三种部署形态的逐项配置、鉴权与签名、字段与枚举口径、接入最短路径与排障，见
[docs/前后端分离与接入指南.md](docs/前后端分离与接入指南.md)。

## 测试

全部套件都用 Node 编写，**无需安装依赖**，配合仓库自带的假模型与假飞书即可完全离线运行：

```bash
cd agent-safe-gate
powershell -NoProfile -ExecutionPolicy Bypass -File tests\run-all.ps1   # 一键跑完全部套件（各自独立端口与数据根，推荐）

# 也可以单跑某个套件（另开终端起假服务）
node tests/mock-ai.mjs 8963                  # 另开终端：确定性假模型
node tests/mock-feishu.mjs 8991              # 另开终端：本机假飞书（账号镜像 + 报销单）
node tests/e2e-account.mjs http://127.0.0.1:8990 http://127.0.0.1:8991   # 92 项：账号权威、四角色、镜像、静默失败
node tests/e2e-invoice.mjs http://127.0.0.1:8990 http://127.0.0.1:8991   # 52 项：报销单写入口、审核、回退与回退值类型
node tests/e2e-feishu-sync.mjs http://127.0.0.1:8990 http://127.0.0.1:8991 # 55 项：账号同步、口令方案升级、越权
node tests/e2e-p0.mjs http://127.0.0.1:8962                              # 44 项：P0 与文件策略矩阵
node tests/e2e-agent.mjs http://127.0.0.1:8962                           # 39 项：多步代理与管理端工具
node tests/e2e.mjs business http://127.0.0.1:8962                        # 业务链路（阶段名在前）
node tests/e2e.mjs attacks http://127.0.0.1:8962                         # 注入 / 越权 / 路径穿越 / 重放
node tests/e2e.mjs bruteforce http://127.0.0.1:8962                      # 后台爆破
node tests/frontend-check.mjs AiApprovalServer/wwwroot                    # 前端静态自检
```

> **参数顺序**：`e2e.mjs` 是 `阶段名 地址`（阶段在前）；账号、报销单与账号同步套件接 `服务地址 假飞书地址`；其余只接地址。
> **限流阈值**：越权用例会累加攻击计分，批量跑验收时必须放宽
> `Limits__WafStrikesBeforeBan`、`Limits__HoneypotStrikesBeforeBan`、`Limits__LoginPerFiveMinutesPerIp`（`run-all.ps1` 已代劳）。
> **离线全绿基线**：目前 386 项断言通过（详见 [docs/测试与验收.md](docs/测试与验收.md)）。

完整启动方式、前置条件与"如何新增一个用例"见 [docs/测试与验收.md](docs/测试与验收.md)。

## 技术选型

- **ASP.NET Core 8 最小 API**，单进程、单可执行文件。
- **零第三方 NuGet 依赖**：JWT（HMAC-SHA256 自实现紧凑序列化）、PBKDF2-HMAC-SHA256（默认 120 万次迭代 + 每账号随机盐 + 服务端密钥）、AES-256-GCM、`System.Text.Json` —— 依赖越少，可审计面越小。
- **JSON 文件即数据库**：原子写（临时文件 + 替换）+ `.bak` 备份 + 独占文件锁；审计链支持多实例并发追加（写前重读尾部校准链头）。
- **前端零依赖**：原生 JS + `textContent`，不使用 `innerHTML`/`eval`，与严格 CSP 兼容。

## 已知边界（有意为之）

- **账号权威只在本机 JSON**：飞书用户表是镜像，镜像失败不影响任何账号功能，"飞书有、本机无"的账号永远登不进来（除非管理员显式执行账号同步把它补进本机；同步只补不改，且导不出超管）。
- **报销单写入口唯一**：协作方前端不直连飞书写库，所有写操作经本服务校验、盖章、快照与审计。
- **批量 / 整目录删除不支持**：空路径与目录路径会被明确拒绝，只能逐条删除、每条单独审批。
- **删除报销单是可回退的**：删除前存整行快照，管理员可按日志重建（飞书会重新分配单号）。
- **共享区写操作永远需要人工审批**，不受"私人区免审批"开关影响。
- **管理员只读的 AI 助手**：管理端 AI 不能审批、不能执行、不能回退，避免"AI 自我批准"。
- 这不是生产级多租户平台：**没有数据库、没有分布式锁、没有水平扩展设计**，定位是**可审计的参考实现**。
